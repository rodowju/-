# 게임 디자인 문서 (GDD) v0.1 — 가칭 "FREEZE"

> 상태: 초안. 모든 수치는 **초기 튜닝값(가설)**이며 플레이테스트로 확정한다.
> 가칭은 상표 검색 전이다. 출시명은 별도 확정 필요.

## 1. 한 줄 정의
술래가 뒤돌아보는 동안 멈추고, 돌아선 사이에 달려 결승선에 닿는 **한 손 리듬 러너** (모바일 웹, 2D).

## 2. 설계 원칙
1. **10초 이해:** 설명 없이 "누르면 달리고, 떼면 멈춘다"가 전부.
2. **억울함 제로:** 탈락 원인이 항상 눈에 보인다 (리플레이).
3. **실력이 보이는 단순함:** 룰은 하나, 숙련도는 타이밍에서 갈린다.
4. **공정성 우선:** 판정은 결정론적 시뮬레이션. 유료 요소는 외형만.
5. **IP 독립:** 원작 명칭·캐릭터·의상·음악·대사 미사용. 메커닉만 차용.

## 3. 플랫폼/화면
- 모바일 웹 우선, **세로(portrait) 고정**, 한 손 엄지 조작.
- 탑뷰 2D: 술래는 화면 상단, 플레이어는 하단에서 위로 달린다. 원근은 스케일로 표현.
- 목표: 중급 모바일 60fps, 초기 로딩 번들 < 3MB (목표치).

## 4. 코어 루프

### 4.1 입력
| 입력 | 동작 |
|---|---|
| 화면 아무 곳 홀드 | 달리기 (가속) |
| 릴리즈 | 정지 (제동 80ms) |

이동 방향 조작 없음 (단일 레인). 햅틱은 지원 기기에서 술래 회전과 탈락 시 진동.

### 4.2 술래 사이클
```
[Chant 노래] → [Turn 회전 300ms] → [Watch 감시] → [Turn-back 300ms] → 반복
```
- **Chant:** 박자(beat) 기반 구호. 박자는 화면 펄스와 소리로 동시 제공 (소리 없이도 플레이 가능). 가사는 현지화하되 **길이는 박자 클록이 결정**하여 언어와 무관하게 동일.
- **Turn:** 술래가 돌아서는 300ms 연출. 이 구간은 **아직 안전**하다 (위험-보상의 핵심).
- **Watch:** 감시 구간. 판정 활성.

### 4.3 물리/판정 (고정 60Hz tick, 결정론적)
| 항목 | 초기값 |
|---|---|
| 최대 속도 | 5.0 m/s |
| 가속 시간 (홀드 → 최대) | 1.2 s |
| 제동 시간 | 80 ms |
| 감시 허용 속도 `v_tol` | 0.3 m/s |
| 판정 유예 `grace` (Watch 시작 후) | 100 ms |
| 안전 릴리즈 마감 `D` | Watch 시작 + 2 tick (≈33 ms, 제동·유예에서 파생) |

탈락 조건: Watch 시작 + `grace` 이후 속도 > `v_tol`.

**가속 구조의 의도:** 연속 달리기는 빠르지만 멈추면 속도가 0으로 돌아가므로, "멈출 때마다 손해"와 "늦게 멈출수록 이득"이 충돌한다. 이것이 재미의 중심 긴장이다.

### 4.4 위험-보상: Close Call
릴리즈가 `D`에 가까울수록 보너스.

| 등급 | 릴리즈 시점 (`D` 기준) | 콤보 |
|---|---|---|
| Perfect | D−100ms 이내 | +2 |
| Great | D−100 ~ −200ms | +1 |
| Good | D−200 ~ −300ms | +0.5 |
| Safe | 그 이전 (Chant 중 정지) | 콤보 유지, 가산 없음 |
| Caught | 탈락 | 콤보 리셋 |

- Close Call은 Turn 연출이 시작된 **이후**에만 의미가 생긴다 (술래가 돌아서는 것을 보고 판단).
- 콤보 배율: 1.0 → 최대 ×5.0 (정수 구간 상한).

### 4.5 점수
```
점수 = 거리 점수(스테이지 클리어 100) + 시간 보너스 + Σ(Close Call 가산) × 콤보 배율
```
- 별 3개 기준: 클리어 / 시간 / 콤보 달성 (스테이지별 조건 노출).
- 정확한 계수는 밸런싱 단계에서 결정.

### 4.6 실패/재도전
- 스테이지당 **목숨 3개**, 탈락 시 해당 스테이지 **시작 지점부터** 재시작(목숨 −1). 체크포인트 없음 (판당 2분 이내로 짧게 유지).
- 목숨 소진 → 리워드 광고로 +1 부활, 또는 처음부터.

## 5. 탈락 리플레이 (차별화 3번)
탈락 직후 자동 재생 (약 2.5초).
1. 최근 3초를 입력 로그로 **결정론적 재현**.
2. 탈락 프레임에서 정지, 0.5초 슬로모션.
3. 오버레이: "움직임 감지 0.9 m/s (허용 0.3)" 및 정지해야 했던 시점 마커.
4. 버튼: 재도전 / 공유(후속, 이미지 또는 짧은 클립).

구현 전제: 시뮬레이션이 렌더링과 분리되어 있고 입력 이벤트가 `(tick, down|up)`로 기록될 것. 이 구조는 이후 멀티플레이 서버 검증에도 그대로 쓰인다.

## 6. 난이도 곡선 (30스테이지 MVP)
| 구간 | 트랙 길이 | Chant 길이 | Watch 길이 | 봇 수 | 특징 |
|---|---|---|---|---|---|
| 1–3 (튜토리얼) | 40 m | 3.0 s 고정 | 1.5 s | 0 | 시각 힌트 상시, Assist ON |
| 4–10 | 60 m | 2.5–3.5 s | 1.2–1.8 s | 4 | 박자 일정, 길이만 변동 |
| 11–20 | 80 m | 1.8–3.5 s | 0.9–1.8 s | 8 | 템포 가속, Watch 랜덤화 |
| 21–30 | 100 m | 1.2–3.5 s | 0.6–1.5 s | 12 | 짧은 Chant, 긴 트랙 |

**Assist 모드 (동적 난이도):** 초반 스테이지에서 `grace` +60ms. 연속 성공 시 단계적으로 해제. 해제는 유저에게 알리지 않고 점진 적용한다 (효과는 플레이테스트로 검증).

**후속(MVP 제외):** 페이크 회전, 불규칙 박자, 시야각 제한, 데일리 챌린지.

## 7. 봇 (경쟁자)
- 목적: 혼자서도 경쟁 긴장감을 만들고, 이후 멀티플레이 유저 풀 부족 시 대체.
- 시드 기반 결정론적 행동. 난이도 파라미터: 반응 지연, 실수율.
- 탈락 연출은 **비폭력** 처리: "얼어붙음/유령화" (스토어·광고 네트워크 정책 대응, 연령 등급 고려).
- 순위는 결승 도착 순서로 결정.

## 8. 경제/수익화
### 8.1 재화
- **코인(소프트):** 스테이지 클리어, 별, 콤보로 획득. 스킨 구매에 사용.
- 하드 재화는 MVP에서 두지 않는다 (복잡도·규제 리스크 회피).

### 8.2 스킨 (외형 전용, 능력치 영향 없음)
| 종류 | 예 |
|---|---|
| 캐릭터 | 복장/색상 |
| 이동 이펙트 | 먼지, 트레일 |
| 정지 이펙트 | Perfect 시 이펙트 |
| 술래 테마 | 배경과 술래 외형 |

- **랜덤 박스(가챠) 미도입.** 직접 구매만. (지역별 확률형 규제 회피)
- 동일 코스 판정에 영향을 주는 시각 요소(판정 힌트 가림 등)는 스킨에 허용하지 않는다.

### 8.3 광고
| 유형 | 위치 | 규칙 |
|---|---|---|
| 리워드 | 부활, 코인 2배, 일일 무료 스킨 체험 | 선택형 |
| 인터스티셜 | 스테이지 종료 후 | 첫 3세션 비노출, 쿨다운 ≥ 3분, 플레이 중 절대 비노출 |
| 배너 | 미사용 | 세로 화면 가림 방지 |

- 광고 제거 IAP(1회)는 후속 검토. 가격과 eCPM은 미검증.

## 9. 유저 흐름 (FTUE)
1. 앱/웹 접속 → 로딩 3초 이내 → 즉시 스테이지 1 (메뉴 없음).
2. 스테이지 1: 손가락 아이콘 + "누르고 있기 / 떼기" 텍스트 대신 **애니메이션 아이콘** (다국어 불필요).
3. 스테이지 3 종료 후 첫 스킨 해금(무료)으로 커스터마이징 소개.
4. 5스테이지 도달 전까지 광고 비노출.

## 10. 접근성/현지화
- 색약 대응: 술래 상태를 색뿐 아니라 **형태/아이콘**으로도 표시 (눈 뜸/감음).
- 소리 없이 플레이 가능: 박자는 항상 시각 펄스 병행.
- i18n 구조: 모든 문자열 키 기반, RTL 대비는 후속.
- 연령 등급/COPPA 등 지역 규제는 출시 전 법무 체크리스트에서 별도 점검 (검증 필요).

## 11. KPI 가설 (검증 전 목표치)
| 지표 | 가설 목표 |
|---|---|
| 첫 세션 5스테이지 도달 | ≥ 60% |
| 평균 세션 길이 | 3–5분 |
| D1 / D7 리텐션 | ≥ 30% / ≥ 8% |
| 탈락 후 즉시 재도전율 | ≥ 70% |

수치는 업계 일반 감각에 기댄 임시 목표이며 근거 자료 아님. 소프트런치 데이터로 대체한다.

## 12. 기술 전제 (아키텍처 문서에서 상세화)
- TypeScript + **Phaser** (2D, 모바일 웹 성능/생태계). 최종 선택은 3단계에서 근거와 함께 확정.
- **시뮬레이션 코어를 렌더링과 분리**: 고정 60Hz tick, 시드 PRNG, 입력 로그 기반.
- 멀티플레이는 동일 코어를 서버에서 재실행해 판정하는 서버 권위 방식으로 확장.

## 14. 미결정 사항
1. 최종 게임명 및 비주얼 아이덴티티 (3안 제시 필요).
2. 가속 구조 유지 여부 (프로토타입 후 재판단).
3. 목숨제 vs 무제한 재도전 (리텐션/광고 수익 트레이드오프).
4. 광고 SDK/플랫폼 (웹 광고 네트워크 비교 필요).
5. 로그인/세이브 방식 (익명 로컬 → 계정 연동 시점).

## 15. 변경 이력
### v0.2 (M3)
- **술래 회전(경고) 시간이 스테이지별로 변한다:** 300 ms (1~10) → 280 → 240 → 200 ms (30). 짧을수록 반응 시간이 줄어 어렵다 (§4.2의 300 ms는 초반 기준값).
- **난이도 앵커 보간:** §6 표의 구간 끝점은 유지하고, 구간 안에서는 선형 보간으로 점진적으로 어려워진다. 30 이후는 30과 동일.
- **par(★2 기준):** 기준 플레이어(반응 8 tick, 매 사이클 D−8 tick 릴리즈)의 완주 시간 × 스테이지별 계수. 계수는 인간형 모델(가설)로 산출한 임시값이며 실제 플레이 데이터로 교체한다.
- **★3 콤보 목표:** 스테이지 1–3 ×2, 4–10 ×3, 11–20 ×4, 21+ ×5.
- **동적 Assist:** 무사고 클리어 −1 tick, 2회 이상 탈락 후 클리어 또는 목숨 소진 +1 tick (상한 4 tick ≈ 66 ms). 유저에게 알리지 않는다.
- **순위 HUD:** 현재 순위와 생존자 수 표시.
- **모델 기반 시뮬레이션 결과(가설):** 반응 시간을 고려한 인간형 모델에서는 평균 플레이어의 생존(클리어) 확률이 전 구간에서 95% 이상이다. 즉 **생존은 쉽고, 난이도는 순위(봇 경쟁)와 ★ 조건에서 나온다.** 이것이 의도("더 쉽게")와 맞는지는 실제 플레이로 확인해야 한다.

### v0.3 (M4)
- **상점/스킨:** 러너(모양+색), 이동 트레일, Perfect 정지 이펙트, 술래 테마 4종 (외형 전용). 술래 테마는 상태 색(초록/노랑/빨강)을 바꾸지 않고 외곽·장식만 추가한다. 러너 색은 트랙 대비 ≥ 3:1, 위험색(빨강)과 구분되도록 테스트로 강제한다. 가격(80~400 코인)은 가설값.
- **코인:** 클리어 시 20 + ★당 10. 가챠/하드 재화 없음. 스테이지 3 첫 클리어 시 첫 스킨(Ember) 무료 해금.
- **광고:** 리워드(목숨 +1 이어하기 — 스테이지당 1회, 코인 ×2)는 유저 선택형. 전면 광고는 4번째 세션부터, 5스테이지 도달 후, 쿨다운 3분, 결과 화면에서만. 현재는 개발용 MockAds이며 실제 SDK는 미선정(`AdsService` 인터페이스 뒤에 있음).
- **i18n:** 한국어/영어. 브라우저 언어 자동 감지, 상점에서 전환. 모든 문자열은 키 기반이며 두 언어의 키/자리표시자 일치를 테스트한다.
- **저장:** 진행·코인·스킨·언어·세션 수를 v2 스키마로 저장. v1 데이터 자동 승격, 손상된 데이터는 안전하게 기본값으로 복구.

### v0.4 (M5)
- **익명 통계:** 설치별 무작위 ID + 허용 키 스키마(개인정보 없음). 상점에서 끌 수 있고, 끄면 미전송 데이터도 폐기. 엔드포인트는 `VITE_ANALYTICS_URL`로 지정(미지정 시 전송 안 함).
- **효과음:** WebAudio 합성음(박자·회전·감시·등급·탈락·클리어). 정보는 항상 시각으로도 제공(접근성). 상점에서 끌 수 있음.
- **PWA:** 설치(홈 화면 추가), 세로 고정, 오프라인 재실행(Phaser 포함 프리캐시), 자동 갱신.
- **성능 계측:** 스테이지당 프레임 간격 p50/p95/max를 `perf` 이벤트로 수집.

- **실시간 대전:** 최대 4명 + 봇, 같은 난이도 구간끼리 매칭, Assist 없음. 결과 화면에서 "온라인 대전" 진입.
